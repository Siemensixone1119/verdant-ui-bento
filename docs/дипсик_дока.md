## Обязательные условия

1. **Сначала изучи реальные файлы Verdant UI.** Не выдумывай API компонентов, файлов, методов, HTML id или названий CSS-классов. Прежде чем менять компонент, прочитай его исходник и места использования в `js/main.js`. Уточни, какие файлы смог прочитать; если файла нет, скажи об этом.
2. **Frontend — строго чистые HTML, CSS, JavaScript.** Не используй React, Vue, Angular, jQuery, TypeScript на фронтенде, npm-пакеты или сборщик, если ТЗ прямо этого не требует.
3. **Сохрани визуальную систему**: Bold/Bento, Powder Blue, светлая/тёмная темы, крупные элементы, мягкие тени, небольшие скругления, выразительные, но не мешающие анимации, Golos Text с fallback. Никаких картинок на фоне, случайных градиентных шаров, шаблонных вычурных украшений. Интерфейс должен выглядеть как аккуратный профессиональный продукт.
4. Сохраняй компоненты в отдельных файлах; создай понятную структуру страниц и JavaScript-модулей. Используй стили Verdant UI, а не переписывай библиотеку с нуля без причины. Все пути импортов должны реально существовать.
5. **Никаких фейковых действий**. Если по заданию данные должны сохраняться, используй настоящий backend/БД. После реального `POST/PATCH/DELETE` обновляй данные через новый GET либо гарантированно синхронизируй локальное состояние. Никогда не показывай «Сохранено» до успешного ответа API.
6. Любой динамический контент, полученный с backend или введённый пользователем, отображай безопасно через `textContent`/создание DOM-узлов. Не помещай непроверенный ввод в `innerHTML`.
7. Реализуй состояние ожидания, ошибку, пустой результат, защиту от повторных отправок, ошибки валидации и ответы 400/401/403/404/409/500 по требованиям задания.
8. Не считай имитационную регистрацию/логин Verdant UI настоящей авторизацией. Реальные логин, роли, хеширование паролей, права доступа, валидацию реализуй на сервере, если этого требует ТЗ. Не храни пароли в браузере.
9. Сохраняй адаптивность на телефоне, планшете, ПК, доступность форм, кликабельные зоны и понятные сообщения. Оставь полноценные header и footer.
10. Не говори, что функциональность реализована, если она не связана с реальными обработчиками и не проверена. Различай: «написано», «собирается», «протестировано».

## Реальные возможности Verdant UI, которые надо учитывать

- `ApiClient` в `js/core/api.js`: конструктор `{ baseUrl='/api', getToken=()=>null }`; методы `get`, `post`, `patch`, `put`, `delete`, `request`. Сам не хранит токен, не выполняет автоматические редиректы. В `request` есть `signal`.
- `DataTable` в `js/components/DataTable.js`: `new DataTable(root, { columns, data, pageSize, onEdit, onDelete, onView, selectable })`; методы `setData`, `setLoading`, `setError`, `reload`, `destroy`. Фильтрация, сортировка, поиск и пагинация — **локальные**, по массиву `data`; `reload()` — только перерисовка без сетевого запроса. Для серверной пагинации доработай механизм явно. Для выделения строк нужен уникальный `row.id`.
- `Form`: `new Form(root, { fields, values, submitLabel, onSubmit })`; методы `setValues`, `render`, `destroy`. Поля `name`, `label`, `type`, `required`, `minLength`, `placeholder`, `options`. Form возвращает строковые значения; преобразуй числа/даты по DTO.
- `Toast.success/error/warn`; `openModal({title,content,actions,drawer})`, `confirmAction(message,onConfirm)`; `Tabs`, `Calendar`, `FileUpload`, `Wizard`, `lineChart`, `dataCards`, `authForm` — сначала изучи исходники, затем применяй.
- Файлы `js/core/demoData.js` и `js/main.js` — **демонстрационный режим**, а не реальная БД и не образец полноценно реализованной авторизации.
- `css/style.css` + `css/bento.css` подключаются в таком порядке. Переключение тем работает через `document.documentElement.dataset.theme` со значениями `light` и `dark` и `localStorage['verdant-theme']`.
- Исходный сайт работает через HTTP-сервер/Live Server (не открывать ES-модули как `file://`).
