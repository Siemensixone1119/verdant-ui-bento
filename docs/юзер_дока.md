# Verdant UI — инструкция по использованию

## 1. Что это

Verdant UI — набор компонентов интерфейса на HTML, CSS и JavaScript без фронтенд-фреймворка. В комплекте одна общая демонстрационная страница. Данные на ней тестовые. Без подключения backend изменения заявок **не сохраняются после перезагрузки**, регистрация и вход **не создают реальную сессию**.

## 2. Как запустить

1. Распакуйте архив и откройте папку `verdant-ui-bento` в VS Code.
2. Запустите **Live Server** на `index.html` либо откройте терминал в этой папке и выполните `python -m http.server 5500` (на Windows при необходимости `py -m http.server 5500`).
3. Перейдите на `http://localhost:5500`.
4. Через кнопку в правой части шапки можно переключать светлую и тёмную темы. Выбор хранится в `localStorage`.

Не запускайте `index.html` двойным щелчком через `file://`: JavaScript использует ES-модули. Для Golos Text нужен доступ к Google Fonts; без интернета используется запасной системный шрифт. Если конкурс полностью офлайн, заранее локально подключите **лицензионно допустимые** файлы выбранного шрифта или оставьте системный.

## 3. Где что находится

| Путь | Назначение |
|---|---|
| `index.html` | Полная showcase-страница: хедер, боковое меню, разделы, футер, контейнеры компонентов |
| `css/style.css` | Базовые стили |
| `css/bento.css` | Bento-оформление, Powder Blue, светлая и тёмная темы, размеры и анимации |
| `js/main.js` | Настройка демонстрационных компонентов и обработчиков событий |
| `js/components/` | Отдельные JS-модули таблицы, формы, календаря, модалок и т. д. |
| `js/core/api.js` | Универсальный клиент `fetch` для REST API |
| `js/core/dom.js` | Вспомогательные методы для безопасного создания DOM |
| `js/core/demoData.js` | Демоданные (не база данных) |

## 4. Как использовать в конкурсном проекте

1. Скопируйте `css/`, `js/components/` и `js/core/` в папку вашего фронтенда. В `js/main.js` хранится демонстрационная логика; не переносите её без разбора.
2. Скопируйте нужные фрагменты разметки из `index.html` (включая `id` контейнера).
3. Подключите CSS в нужном порядке:

```html
<link rel="stylesheet" href="/css/style.css">
<link rel="stylesheet" href="/css/bento.css">
```

4. Подключите **свой** файл приложения, например:

```html
<div id="requestsTable"></div>
<script type="module" src="/js/requests-page.js"></script>
```

5. В `requests-page.js` импортируйте классы из `components/` и настройте их. Пути импортов зависят от расположения вашего файла.
6. Не подключайте одновременно старый демонстрационный `js/main.js` и собственный обработчик к тем же `id`: они начнут конфликтовать.

## 5. Пример: таблица заявок, загружаемая с сервера

Если файл `requests-page.js` находится в папке `js/`:

```js
import { ApiClient } from './core/api.js';
import { DataTable } from './components/DataTable.js';
import { Toast } from './components/Toast.js';

const api = new ApiClient({
  baseUrl: '/api',
  getToken: () => sessionStorage.getItem('token'),
});

const table = new DataTable('#requestsTable', {
  columns: [
    { key: 'id', label: '№', sortable: true },
    { key: 'title', label: 'Название', sortable: true },
    { key: 'status', label: 'Статус', type: 'badge' },
  ],
  data: [],
  onDelete: async (row) => {
    try {
      await api.delete(`/requests/${encodeURIComponent(row.id)}`);
      await loadRequests();
      Toast.success('Заявка удалена');
    } catch (error) {
      Toast.error(error.message);
    }
  },
});

async function loadRequests() {
  table.setLoading(true);
  try {
    const result = await api.get('/requests');
    // Адаптируйте к фактическому формату ответа backend.
    const items = Array.isArray(result) ? result : result.items;
    if (!Array.isArray(items)) throw new Error('Неизвестный формат ответа API');
    table.setData(items);
  } catch (error) {
    table.setError(error);
  }
}

await loadRequests();
```

**Важно:** удаление здесь вызывается сразу. Для подтверждения используйте `confirmAction` (см. ниже). Не выводите успех до завершения запроса. `setLoading(false)` в этой библиотеке приводит к перерисовке; после успешной загрузки достаточно `setData()`.

**Не путайте `table.reload()` с повторным запросом API:** этот метод только перерисовывает таблицу. Для обновления данных вызывайте собственную `loadRequests()`.

## 6. Частые компоненты и их точные методы

### Формы

```js
import { Form } from './components/Form.js';
new Form('#formRoot', {
  fields: [
    { name: 'title', label: 'Название', required: true },
    { name: 'description', label: 'Описание', type: 'textarea' },
    { name: 'status', label: 'Статус', type: 'select', options: [
      { label: 'Новая', value: 'NEW' }, { label: 'Готова', value: 'DONE' }
    ] },
  ],
  submitLabel: 'Сохранить',
  onSubmit: async (data) => { /* await api.post('/requests', data) */ },
});
```

`new Form(root, { fields, values, submitLabel, onSubmit })`. Методы: `render()`, `setValues(values)`, `destroy()`. Поддерживаются поля `text` (по умолчанию), `email`, `password`, `textarea`, `select` и стандартные типы `input`. Часть типов значений возвращается **строками**; числа/даты преобразуйте согласно DTO. Поля с `required`, `minLength` проверяются браузером. Более сложные правила требуется добавить по ТЗ. Подпись кнопки во время отправки меняется на «Сохранение…» независимо от `submitLabel`.

### Таблица

`new DataTable(root, { columns, data, pageSize, onView, onEdit, onDelete, selectable })`.

Методы: `setData(array)`, `setLoading(boolean)`, `setError(error)`, `reload()`, `destroy()`.

Свойства столбца: `key`, `label`, необязательные `sortable: true`, `type: 'badge'`.

Поиск, сортировка и пагинация сейчас **клиентские**, по уже загруженному массиву. Строки должны иметь уникальный `id` для выбора и массовых действий. Серверную пагинацию, серверные фильтры и отдельные DTO необходимо реализовать под фактическое задание; текущий `DataTable` их не поддерживает автоматически.

### Уведомления, модалки и подтверждение

```js
import { Toast } from './components/Toast.js';
import { openModal, confirmAction } from './components/Modal.js';
Toast.success('Сохранено');
Toast.error('Ошибка запроса');
Toast.warn('Проверьте данные');
const close = openModal({ title: 'Подробнее', content: 'Текст' });
confirmAction('Удалить запись?', async () => { /* запрос на сервер */ });
```

Для передачи формы в модалку `content` должен быть DOM-элементом с формой; строковый `content` отображается как **текст**, не как HTML. В `confirmAction` асинхронные ошибки надо самостоятельно перехватывать и показывать пользователю.

### Остальные модули

- `new Tabs(root, [{ label, render: () => DOMElement }])` — вкладки.
- `new Calendar(root, { onSelect: date => ... })` — выбор даты (`Date`).
- `new FileUpload(root, { accept, multiple, onFiles: files => ... })` — **выбор**, не отправка файлов. Для отправки формируйте `FormData`, вызывайте `api.post()` или `api.request()`; `ApiClient` передаёт `FormData` без JSON-заголовка.
- `lineChart(domElement, [12, 17, 25])` — SVG-график чисел. Для пустого массива/одного значения нужна дополнительная обработка в самом компоненте.
- `dataCards(domElement, array, { onClick: item => ... })` — карточки с полями `title`, `description`, `category`, `price`.
- `new Wizard(root, [{ title, description, onFinish? }])` — демо-переходы по шагам, не готовый менеджер сложных форм.
- `dropdown(button, [{ label, action }])` — выпадающее меню.
- `authForm(root, { mode: 'login'|'register', onSubmit })` — визуальная форма, **не** готовая авторизация; для неё нужен реальный API.
- `Badge(text, tone)` — возвращает DOM-элемент статуса.
- `tooltip(node, message)` — нативная подсказка через `title`.

## 7. Работа с API: главное

```js
const api = new ApiClient({ baseUrl: '/api', getToken: () => sessionStorage.getItem('token') });
await api.get('/requests');
await api.post('/requests', { title: 'Новая' });
await api.patch('/requests/1', { status: 'DONE' });
await api.put('/requests/1', { title: 'Обновлено' });
await api.delete('/requests/1');
```

`ApiClient` умеет отправлять JSON, `FormData`, прокидывать `Authorization: Bearer <token>`, читать JSON/текстовый ответ, возвращать статус ошибки в `error.status` и её содержимое в `error.data`. **Он не управляет токенами или редиректами автоматически**. Если backend использует cookie-сессии, у клиента сейчас нет настройки `credentials`; клиент требуется адаптировать. Для frontend на другом origin понадобится корректный CORS на backend.

Токен в `sessionStorage` приведён **только как простой пример интеграции**. Если сервер поддерживает защищённую cookie-сессию, используйте её и соответствующие меры защиты. Никогда не храните пароли в `localStorage` или `sessionStorage`.

## 8. Как работать с завтрашним заданием

1. Прочитайте ТЗ полностью. Выпишите страницы, роли, сущности, поля, правила валидации и действия пользователя.
2. Нарисуйте последовательность экранов: регистрация → вход → просмотр → создание → редактирование → удаление → выход (если требуются).
3. Опишите DTO/маршруты backend: HTTP-метод, URL, тело запроса, формат ответа, возможные ошибки.
4. Для каждой страницы берите готовые стили и компоненты, адаптируя **только нужное**.
5. Подключите реальные запросы, удалите демоданные там, где нужны данные из БД.
6. Проверьте все функциональные сценарии после обновления страницы, при ошибках API, на узком экране и в обеих темах.

## 9. Быстрый чек-лист перед сдачей

- [ ] Приложение запускается через HTTP, нет ошибок в Console и Network.
- [ ] Все страницы, нужные по заданию, доступны; навигация работает.
- [ ] Есть реальные запросы к API для чтения/записи данных; данные сохраняются в БД.
- [ ] Обновление страницы не теряет уже сохранённые сервером данные.
- [ ] Регистрация/вход/роли работают на сервере, если требуются.
- [ ] Формы блокируют некорректные значения; сервер дополнительно проверяет данные.
- [ ] Таблицы корректно отображают данные, пустой список, загрузку и ошибку.
- [ ] Кнопки создают/изменяют/удаляют реальные записи и показывают результат только после ответа API.
- [ ] Нет демо-уведомлений «успех», если действие фактически не выполнено.
- [ ] Адаптивный интерфейс проверен на мобильной ширине; обе темы читаемы.

## 10. Что нельзя считать готовым из коробки

Серверная авторизация, настоящее хранение данных, управление ролями, безопасная загрузка файлов, серверная пагинация и комплексная логика многошаговых форм в комплект не входят: их необходимо реализовать по заданию. Проверяйте результат в браузере: не все интерактивные состояния библиотеки ранее проходили полноценные сквозные тесты.
